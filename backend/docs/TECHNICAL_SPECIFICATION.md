# Технічне завдання
# Веб-система для аналізу біометричних показників стресу

## 1. Загальні відомості

### 1.1 Повна назва системи
Веб-система для аналізу біометричних показників стресу (Biometric Stress Analysis System)

### 1.2 Призначення системи
Система призначена для:
- Збору та зберігання біометричних даних користувачів
- Аналізу рівня стресу на основі біометричних показників
- Генерації персоналізованих рекомендацій для зниження стресу
- Моніторингу динаміки стресових показників у часі

### 1.3 Цільова аудиторія
- Користувачі, які стежать за своїм здоров'ям
- Медичні працівники (лікарі, психологи)
- Адміністратори системи

## 2. Функціональні вимоги

### 2.1 Управління користувачами
- Реєстрація нових користувачів
- Авторизація за допомогою JWT токенів
- Управління профілем користувача
- Різні ролі: USER, DOCTOR, ADMIN

### 2.2 Управління біометричними даними
Система повинна збирати наступні показники:
- Частота серцевих скорочень (пульс)
- Артеріальний тиск (систолічний/діастолічний)
- Температура тіла
- Рівень кортизолу (гормон стресу)
- Якість та тривалість сну
- Частота дихання
- Рівень насичення кисню крові
- Рівень фізичної активності

### 2.3 Аналіз стресу
Алгоритм аналізу включає:
- Багатофакторну оцінку стресу з ваговими коефіцієнтами:
  - Серцево-судинна система (30%)
  - Термальні показники (15%)
  - Біохімічні показники (25%)
  - Якість сну (20%)
  - Дихальна система (10%)
- Визначення рівня стресу: LOW, MODERATE, HIGH, CRITICAL
- Розрахунок загального індексу стресу (0-100)

### 2.4 Система рекомендацій
Автоматична генерація рекомендацій за категоріями:
- Фізична активність
- Харчування
- Сон
- Релаксація
- Медичні консультації
- Зміни способу життя

## 3. Нефункціональні вимоги

### 3.1 Продуктивність
- Час відгуку API: < 500 мс для більшості запитів
- Підтримка мінімум 100 одночасних користувачів
- Час аналізу біометричних даних: < 2 секунди

### 3.2 Безпека
- Шифрування паролів за допомогою BCrypt
- JWT токени для авторизації
- HTTPS для всіх з'єднань
- Валідація вхідних даних
- Захист від SQL-ін'єкцій та XSS атак

### 3.3 Надійність
- Доступність системи: 99.5%
- Резервне копіювання даних
- Обробка помилок та логування

### 3.4 Масштабованість
- Горизонтальне масштабування backend
- Використання Docker контейнерів
- Підтримка балансування навантаження

## 5. Архітектура системи

### 5.1 Шарова архітектура
```
├── Controller Layer (REST API)
├── Service Layer (Business Logic)
├── Repository Layer (Data Access)
└── Entity Layer (Domain Models)
```

### 5.2 Принципи SOLID
- **S**ingle Responsibility: Кожен клас має одну відповідальність
- **O**pen/Closed: Відкритий для розширення, закритий для модифікації
- **L**iskov Substitution: Підтипи можуть замінювати базові типи
- **I**nterface Segregation: Багато специфічних інтерфейсів
- **D**ependency Inversion: Залежність від абстракцій

### 5.3 Патерни проектування
- **Strategy Pattern**: Різні алгоритми аналізу стресу
- **Factory Pattern**: Створення рекомендацій
- **Repository Pattern**: Абстракція доступу до даних
- **Builder Pattern**: Створення складних об'єктів
- **Chain of Responsibility**: JWT фільтр аутентифікації

## 6. База даних

### 6.1 Основні таблиці
- **users**: Користувачі системи
- **biometric_data**: Біометричні показники
- **stress_analysis**: Результати аналізу стресу
- **recommendations**: Рекомендації

### 6.2 Зв'язки
- User → BiometricData (One-to-Many)
- User → StressAnalysis (One-to-Many)
- BiometricData → StressAnalysis (One-to-One)
- StressAnalysis → Recommendation (One-to-Many)

## 7. API Endpoints

### 7.1 Authentication
- POST /api/auth/register - Реєстрація
- POST /api/auth/login - Вхід

### 7.2 Users
- GET /api/users/{id} - Отримати користувача
- PUT /api/users/{id} - Оновити профіль
- DELETE /api/users/{id} - Видалити користувача (Admin)

### 7.3 Biometric Data
- POST /api/biometric-data - Додати дані
- GET /api/biometric-data/user/{userId} - Отримати всі дані користувача
- GET /api/biometric-data/user/{userId}/latest - Останні дані

### 7.4 Stress Analysis
- POST /api/stress-analysis/analyze/{biometricDataId} - Проаналізувати
- GET /api/stress-analysis/user/{userId} - Історія аналізів
- GET /api/stress-analysis/user/{userId}/average-score - Середній показник
